# 月白动作库

`moon-bai/manifest.json` 对应 `moon_bai.mp4`，素材来自仓库 `assets/bg-images/bg56`；每条记录保留原始来源。

- `idle`：自然待机，静音循环。
- `hair`：拨头发。
- `smile`：微笑。
- `cute`：俏皮表情。
- `watermelon`：**缺素材，未实现播放**，请求时提示尚未就绪。

现有源素材约 960～1024 像素，统一保留画面、补边为 1024×1024，24 fps，H.264，无音轨。桌面横屏使用环境填充，**不是原生高清横屏素材**。补齐原生 1920×1080 同一人物、同一服装/场景的视频后才能替换此限制；不能用放大声明画质提升。

客户端顺序预载约 7 MB 素材，使用对象 URL；切换人物时取消加载、回收缓存。月白取消定时随机动作，仅响应明确动作请求，以及问候/感谢后的微笑（自动微笑至少间隔 30 秒）。动作通常等口播结束 450 毫秒后执行；无语音输出时在提交后 12 秒的安静窗口执行。新请求覆盖旧请求，过期或隐藏窗口时清掉请求。发声始终优先，不等待动作。命令识别在本地进行，不调用额外模型，不等待动作生成。

文字/语音通过现有 `sendText` 提交成功后触发 `dsh-voice:submitted`。例如“拨一下头发”“笑一个”“卖萌一下”。否定指令不触发。普通文字聊天页和独立陪伴页共享动作层。

增加吃西瓜动作：先准备同一人物的完整动作片段（从待机姿势进入、拿起西瓜、咬一口、放下、回到待机），放入此目录，在 manifest 的 actions 加入 `watermelon` 的 file/label/source/duration，并移除 unavailable 对应项。人物吃东西时不同时播放口播，语音优先。

验证：`node --experimental-strip-types --test desktop/action-policy.test.cjs`；桌面 `--all-avatar-continuity-test` 逐个验证当前已配置形象的首帧覆盖、真实口播播放和待机姿势恢复。结果保存于 `.local/desktop/all-avatar-continuity-test.json`，逐帧状态见同目录 `continuity-<形象文件名>.json`。

月白过渡：动作素材使用同一待机画面的 240 毫秒入场/收尾融合；动作收尾时背景停在匹配的 0.5 秒姿势。口播音频立即播放，待解码帧到达后才移走待机层；口播结束时保留末帧，待机按口播时间对齐源视频姿态后接回。此方案改善已有片段的切换，仍不能补出素材没有的连续身体运动。其他角色现已共用首帧交接和姿势对齐策略，但仍使用自己的口型模板，不播放月白的动作。
